# TravelPlus 改造实施计划（Java 24 环境迁移 + 全链路场景替换）

> ⚠️ 修正注记（2026-08）：本文档中"Redis 6379 / company-agent-redis（复用）"的表述为早期阶段事实——6379 实为其他项目 Redis；TravelPlus 现用 Redis 集群（6380/6381 + 哨兵 26379~81，密码 123456），见 docker/redis-sentinel/docker-compose.yml 与 AGENTS.md。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 hm-dianping（Spring Boot 2.3.12 / Java 8）先迁移到 Java 24（Spring Boot 3.5.9）可编译可运行，再全链路语义改造为旅游平台 TravelPlus，全程零逻辑改动。

**Architecture:** 阶段 A 升级依赖栈（Boot 3.5.9 + MyBatis-Plus 3.5.17 + mysql-connector-j + Lombok 1.18.38）并完成 javax→jakarta 机械迁移，用 Docker 提供 MySQL(3307)/Kafka(9092) 基础设施，编译+启动冒烟验证。阶段 B 按"长词优先"顺序做全链路命名替换（Java→资源→SQL→文档），每阶段编译门禁 + 残留 grep 兜底。

**Tech Stack:** Java 24, Spring Boot 3.5.9, MyBatis-Plus 3.5.17 (spring-boot3-starter), spring-kafka (Boot 托管), Redisson 3.50.0, Hutool 5.8.36, Caffeine, MySQL 8.0 (Docker), Redis 7.2 (复用现有容器), Apache Kafka 3.7.0 (Docker), Maven 3.9.11。

## Global Constraints（全局铁律，每个任务隐式包含）

1. **零逻辑改动**：所有方法体、控制流、事务、异常处理保持原样；不做任何代码清理、不修任何 bug、不加新功能。
2. **半成品保留**：`KafkaConfig` 注释掉的 Bean、`SeckillVoucherConsumer` 注释掉的 `@KafkaListener`、`seckill.lua` 注释掉的 xadd 行——保持注释状态，仅改其中出现的标识符；`logout()` 占位返回保留；未使用变量（`int r = result.intValue();`）保留；课程章节标记【秒杀链路消息队列使用】-1/-2/-3、【多级缓存改造】、【滑动窗口限流】等编号注释保留。
3. **唯一例外**：框架升级强制的 API/命名空间迁移（javax→jakarta、依赖版本、配置属性改名），行为必须等价。
4. **图片路径白名单（永不替换）**：`/imgs/blogs/`、`/blogs/{}/{}` 存储格式串、所有 `https://` CDN 图片 URL、`/types/*.png`、`/imgs/icons/*`。
5. **批量文本替换必须使用 `[System.IO.File]::ReadAllText/WriteAllText`**（UTF-8 无 BOM）。禁止 PowerShell `Set-Content -Encoding UTF8`（会写入 BOM，javac 报 `illegal character: '\ufeff'`）。
6. 工作在 `travelplus-migration` 分支（已创建）。每个任务结束必须 commit。
7. Maven 命令统一用全路径：`C:\Users\lenovo2026\tools\apache-maven-3.9.11\bin\mvn.cmd`（下文记作 `$MVN`）。
8. 每个任务完成后向 `docs/travelplus/03-过程记录.md` 追加一条记录（时间戳 + 任务号 + 做了什么 + 验证结果），只追加不覆盖。

```lua
-- 1.参数列表
-- 1.1.门票id
local ticketId = ARGV[1]
-- 1.2.用户id
local userId = ARGV[2]
-- 1.3.订单id
local orderId = ARGV[3]

-- 2.数据key
-- 2.1.库存key
local stockKey = 'seckill:stock:' .. ticketId
-- 2.2.订单key
local orderKey = 'seckill:order:' .. ticketId

-- 3.脚本业务
-- 3.1.判断库存是否充足 get stockKey
if(tonumber(redis.call('get', stockKey)) <= 0) then
    -- 3.2.库存不足，返回1
    return 1
end
-- 3.2.判断用户是否下单 SISMEMBER orderKey userId
if(redis.call('sismember', orderKey, userId) == 1) then
    -- 3.3.存在，说明是重复下单，返回2
    return 2
end
```
